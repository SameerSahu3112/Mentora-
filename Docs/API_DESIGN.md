# Mentora API Design

**Status:** Phase 0 — Architecture review document (pre-implementation)  
**Base path:** `/api/v1`  
**Auth:** Session/cookie-based (secure, HTTP-only); no long-lived tokens in localStorage  
**Format:** JSON  
**Source of truth:** PRD, AGENTS.md, docs/DATABASE_DESIGN.md

---

## 1. Conventions

| Convention | Detail |
|------------|--------|
| Base URL | `https://api.mentora.example.com/api/v1` (Render) or `http://localhost:8000/api/v1` (local) |
| Content-Type | `application/json` |
| Dates | ISO 8601 UTC in API; frontend converts to Asia/Kolkata for display |
| Primary keys | UUID strings |
| Errors | RFC 7807-style Problem Details: `{ type, title, status, detail, instance }` |
| Pagination | `?page=<int>&page_size=<int>`; response: `{ items, total, page, page_size, total_pages }` |
| Rate limiting | Login and abuse-prone endpoints (e.g., application submission, payment recording) |
| CORS | Restricted to known frontend origins |
| OpenAPI | Auto-generated by FastAPI at `/docs` and `/openapi.json`; maintained and versioned |

| Endpoint | Method | Auth | Description |
|----------|--------|------|-------------|
| `/auth/register` | POST | Public | Student signup. Returns user + student profile + generated Student ID. |
| `/auth/login` | POST | Public | Student ID or email + password. Sets secure HTTP-only session cookie. |

## 7. Request/Response Schema Examples

### Student Registration
**POST** `/auth/register`
```json
{
  "full_name": "Aarav Sharma",
  "class": "11",
  "email": "aarav@example.com",
  "phone": "+919876543210",
  "school_name": "Delhi Public School",
  "coaching_institute_name": null,
  "password": "strongPassword123"
}
```
**Response 201:**
```json
{
  "user": { "id": "uuid", "email": "aarav@example.com", "role": "student", "is_active": true },
  "student_profile": { "id": "uuid", "student_id": "MENT-2026-0001", "full_name": "Aarav Sharma", "class": "11" }
}
```

### Create Batch Application
**POST** `/student/applications`
```json
{
  "course_id": "uuid",
  "batch_id": "uuid"
}
```
**Response 201:** Application created; intro session auto-created. Notification sent to student and Admins.

### Record Manual Payment
**POST** `/admin/payments`
```json
{
  "student_profile_id": "uuid",
  "course_id": "uuid",
  "batch_id": "uuid",
  "original_amount": 299.00,
  "discount": 0.00,
  "final_amount": 299.00,
  "payment_date": "2026-11-15",
  "payment_method": "bank_transfer",
  "transaction_reference": "REF123456"
}
```

### Propose Critical Action (Two-Admin Approval)
**POST** `/admin/approvals`
```json
{
  "action_type": "reject_enrollment",
  "payload_snapshot": {
    "enrollment_id": "uuid",
    "reason": "Non-payment after 14 days"
  }
}
```

### Get Signed Resource Download URL
**GET** `/student/resources/{resource_id}/download-url`
**Response:**
```json
{
  "download_url": "https://storage.example.com/signed/...",
  "expires_at": "2026-11-20T10:00:00Z"
}
```

## 8. Error Conventions

| Status | Meaning | Example |
|--------|---------|---------|
| 400 | Bad request / validation error | Invalid phone format, missing required field |
| 401 | Unauthenticated | Missing or invalid session |
| 403 | Forbidden | Insufficient role or object-level access |
| 404 | Not found | Resource or batch does not exist |
| 409 | Conflict | Duplicate email, batch full, duplicate active enrollment |
| 422 | Unprocessable | Capacity exceeded, enrollment already active |
| 429 | Too many requests | Rate limit exceeded (login) |
| 500 | Internal server error | Unexpected failure |

Error body:
```json
{
  "type": "https://api.mentora.example.com/problems/batch-full",
  "title": "Batch capacity exceeded",
  "status": 409,
  "detail": "Batch Apex 1.0 has no available seats.",
  "instance": "/student/applications"
}
```

## 9. Authorization Summary (enforced server-side)

- **Public endpoints:** No session required.
- **Student endpoints:** Requires `student` role; object-level: student accesses only their own applications, enrollments, resources covered by active enrollments, own bookmarks/completions/bookings.
- **Teacher endpoints:** Requires `teacher` role; object-level: teacher accesses only assigned batches, students in those batches, own resources, own bookings, own attendance markings.
- **Admin endpoints:** Requires `admin` role; two-Admin approval for critical actions.
- **Never rely on hidden UI controls as authorization.**
